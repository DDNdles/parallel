# parallel 插件开发指南

插件 = 一个目录：`plugin.json`（清单）+ `index.ts` 或 `index.js`（`setup(ctx)` 入口）。
最省事的路径：复制 `examples/hello-plugin/` 改。

## 三类来源

| 来源 | 位置 | 说明 |
|------|------|------|
| 内置 | `src/plugins/` | 随包分发，不可卸载 |
| 示例 | `examples/` | 模板，抄完放用户目录 |
| 用户自建 | `data/plugins/<id>/` | **运行期放入即被发现**：QQ 里 `/插件 安装`（主人）或桌面端扫描安装，热载入不重启 |

## 清单（plugin.json）

```jsonc
{
  "id": "my-plugin",              // 必填，kebab-case，全局唯一
  "name": "我的插件",
  "version": "0.1.0",
  "description": "……",
  "category": "tool",             // core | persona | tool | fun | info | system
  "permissions": ["network"],     // 声明式权限，缺权调用在容器层被拒
  "defaultGroupState": "off",     // 本系统默认全部关闭；off = 新群不启用
  "core": false,                  // core 插件不可停用/卸载
  "locked": false,                // persona 类默认 true：仅主人可开关/查看
  "personas": [],                 // persona 类插件填人格 id
  "userConfig": {                 // 用户可调配置（UI 渲染表单）
    "apiKey": { "type": "string", "default": "", "description": "…", "secret": true }
  },
  "mcpServers": {                 // stdio MCP 工具服务（需 network 权限）
    "srv": { "command": "node", "args": ["mcp-server.mjs"], "env": { "KEY": "${userConfig.apiKey}" } }
  }
}
```

> **敏感信息红线**：API key/token 一律 `secret: true` 走配置注入（存 `data/secrets.json`），清单文件里不落密钥；`${userConfig.xxx}` 可在 mcpServers 的 command/args/env 里插值。UI 上脱敏显示。

## setup(ctx) 能做什么

```ts
export function setup(ctx) {
  // —— LLM 工具（agent loop 可调用；JSON Schema 描述参数）——
  ctx.llm.registerTool({
    name: 'my_tool', description: '……',
    parameters: { type: 'object', properties: { q: { type: 'string' } }, required: ['q'] },
    minRole: 'member',            // 可选：'admin' | 'owner'
    async handler(args, tctx) {   // tctx: { event, chat, role }
      return '给模型看的文本结果';
    },
  });

  // —— 聊天命令（QQ 侧 /命令 与桌面端补全共用）——
  ctx.registerCommand({
    name: '我的命令', aliases: ['alias'], description: '……', minRole: 'admin',
    async handler(args, event) { return { text: '回复' }; },  // 也可 { segments } 或 { sandboxFile: '沙箱内路径' }
  });

  // —— 沙箱（需 fs.sandbox / sandbox.exec 权限）——
  await ctx.sandbox.run(chat, { language: 'python', code: 'print(1)' });
  ctx.sandbox.write(chat, 'note.txt', '内容');   // 只能写本会话沙箱，越界抛错

  // —— 用户记忆（需 memory.read / memory.write 权限）——
  ctx.memory.addFact(userId, { content: '喜欢猫' });
  ctx.memory.getAttr(userId, 'affection');

  // —— 定时任务（需 schedule 权限；proactive 任务默认关闭，主人 UI 开启）——
  ctx.schedule.register({ id: 'push', dailyAt: '09:00', proactive: true, handler() {} });

  // —— 插件专属 KV 与数据目录 ——
  ctx.state.set('n', 1); ctx.state.get('n', 0);
  ctx.pluginDataDir;  // 持久目录

  // —— 事件 / 定时器 / 清理登记（卸载时全部自动回收，不留孤儿）——
  ctx.on('session.log', (e) => {});
  ctx.setInterval(() => {}, 1000);
  ctx.onDispose(() => childProc.kill());

  // —— 生命周期钩子 ——
  ctx.hooks.onChatMessage = (event) => {};             // Pipeline 早期
  ctx.hooks.beforeLLM = (req) => req;                  // 组 prompt（人格插件插槽）
  ctx.hooks.afterLLM = (req, reply) => reply;          // 输出校验（persona checker 插槽）
  ctx.hooks.onUnload = () => {};                       // 最后清理机会
}
```

## 分群开关的后果（务必理解）

每个群对每个插件有独立开关，**默认全部关闭**。某群禁用你的插件时，后果严格成立：

1. 该群的 LLM 工具列表里**没有**你的工具（不是注册了但拒绝——省 token 且防误触）；
2. 命令不可用；普通群成员**完全看不到**插件存在（`/帮助`、`/插件 列表` 都不显示）；
3. 钩子（onChatMessage/beforeLLM/afterLLM）不投递；
4. 开关权限 = 该群群管理员/群主/主人（persona 类仅主人）。

## 稳健性要求（内核替你兜底的部分）

- 插件抛错被 `guarded()` 隔离，不会带崩内核；**连续 3 次同错自动停用**并私聊主人。
- 卸载/重载时：`onUnload` → disposers 逆序（定时器、子进程、监听器全清）→ 模块替换（时间戳破缓存）。
- 配置保存后自动重载插件使新值生效。

## persona 插件（人格）的特殊形态

人格插件提供 `personas/` 目录：

```
personas/<id>/card.json      人设卡（name/description/personality/scenario/first_mes）
personas/<id>/fewshot.json   { post_history_instructions, examples: [{user, assistant}] }
personas/<id>/lorebook.json  { entries: [{keys, content, priority, constant, tokenBudget}] }
```

内核每次组 prompt 自动装配五插槽；`chat` 插件是参考实现。`locked: true` 使普通群成员不可切换、不可查看内容（详情接口脱敏、工具层拒绝）。
