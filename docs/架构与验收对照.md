## §3 红线对照

1. **接入**：`adapters/onebot11.ts` 仅 OneBot 11 反向 WS 服务端；token 强制（`Bearer` 或 `?access_token=`），错误 token 连接被拒（E2E 验证）；全仓库无 NapCat 任何引用（仅文档红线声明处提及"不支持"）。
2. **沙箱边界**：见 §2.3。
3. **风控克制**：`ChatService`（令牌桶+随机抖动+超长分段）；`Pipeline.isAwake` 群聊仅 @/回复（命令显式豁免）；`Scheduler` proactive 门控默认关；UI 设置页标注。
4. **健壮性**：`atomicWriteJson`（tmp+rename+bak×3，E2E 单测覆盖）；`container.guarded`（崩溃隔离+同错 3 次自动停用+通知主人，E2E 覆盖）；卸载统一 deactivate（disposers 逆序：定时器/子进程/监听器/MCP 客户端；调度任务经 `scheduler.unregisterPlugin` 注销，单测覆盖）。
5. **权限**：`resolveRole` 三级；命令 minRole、工具 minRole/ownerOnly、persona locked、memory/sandbox/schedule 权限门控全部容器层强制（E2E 越权用例）。
6. **可测试**：`test/helpers/mock-onebot.ts` 模拟协议端 + UI 注入通道（E2E「桌面端注入」），无真号跑通全链路。
7. **敏感信息**：`secrets.json` 集中（uiToken/onebotAccessToken/providerKeys/pluginSecrets）；清单无密钥；UI 脱敏；mcpServers env 支持 `${userConfig.xxx}` 注入。
